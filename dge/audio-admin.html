2. Options

A chanted shloka follows a vṛtta (metrical pattern), so it's rarely shorter than ~10–15 seconds — anything shorter than "Minimum shloka length" gets merged into its neighbour instead of kept as its own clip. "Minimum gap" is a floor: a detected silence shorter than this is treated as an in-verse breath, not a real boundary between shlokas, even if auto-detect would otherwise have used a shorter value. If auto-detect still splits badly on a real recording (background noise can make its threshold too permissive), set an explicit dB override above and re-run — no need to wait on us to retune it.
At least one of the two above should stay checked, or there's nothing to produce. The edge cushion applies to both, so a clip and a JSON-seek of the same chunk always play the same audio.

4. Push to bhumandala-audio-data

Scope this token to ONLY bhumandala-audio-data. GitHub → Settings → Developer settings → Fine-grained tokens → Repository access: "Only select repositories" → bhumandala-audio-data → Permissions: Contents: Read and write. This page hardcodes its target repo (no picker), but that only helps if the token itself can't reach anywhere else — a broadly-scoped token pasted here could still write elsewhere if this page had a bug, so don't rely on the UI alone.
Pushes go through GitHub's Git Data API (blob → tree → commit, all files in one atomic commit), not the plain "upload a file" API — that raises the reliable per-file ceiling to roughly GitHub's own ~100 MB hard limit (without Git LFS), well past the 25 MB cap you'll hit dragging a file into the GitHub website (that limit is specific to the website's uploader, not the API). A single file anywhere near 100 MB still won't go through, though — use Download above instead and place it wherever you like.
Prefilled from the uploaded filename when you first pick a file — edit it to anything you like. GitHub has no real "create folder" step: typing a new path and pushing to it creates it automatically.
